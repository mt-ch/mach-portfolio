# Custom cursor interaction model: event delegation

`CustomCursor` is mounted once in `app/(site)/layout.tsx` and, like `PageTransitionProvider`, never remounts per route. The original implementation scanned the DOM with `document.querySelectorAll` at mount time and attached `mouseenter` / `mouseleave` listeners to each matched element. Because the mount happens once per full page load, that scan missed every element that appears later: the chat drawer's buttons (its DOM is not rendered until first open), and every link or "View Project" row on a page reached by client-side navigation. A hovered element that unmounted mid-interaction left the cursor frozen in its previous shape, because no `mouseleave` fired.

Issue #129 replaces the scan with **event delegation**. The cursor attaches one pair of listeners at the document level — `mouseover` / `mouseout`, which bubble (`mouseenter` / `mouseleave` do not, which is why the original code bound per element) — and on each event walks up from the target with `closest('[data-cursor]')` to find the nearest cursor-tagged ancestor. `relatedTarget` is checked so moving between two children of the same tagged element does not thrash the state. This is correct for any element present at any time — current page, next page, late-mounted drawer, 404 page — with no re-scan and no navigation hook for binding.

The stuck-state symptom is handled by a reset to the base variant on three events: a `mouseout` that resolves to no tagged element, a committed route change (`usePathname`), and the chat drawer opening or closing (surfaced to the cursor as a `data-chat-open` attribute on `<html>`, since the cursor lives outside the chat subtree — the same plain-DOM-flag pattern `PageTransitionProvider` uses for `data-page-covered`).

The `data-cursor` attribute API is consolidated to a single required discriminator with three values: `link`, `button`, and `label` (label text from `data-cursor-label`, optional icon key `eye` | `mail` from `data-cursor-icon`). This replaces the earlier scheme where the label variant was triggered by the mere presence of `data-cursor-text`. There is no backwards-compatibility shim — this is an internal attribute contract.

The code lives in `components/ui/cursor/`, split so the variant-selection logic is a pure, dependency-free function (`cursorVariants`) that is the one unit-test seam; `useCursorInteractions` owns the delegated listeners and resets; `useCursorPosition` owns pointer tracking and the `custom-cursor-active` class; `CustomCursor` owns the refs, render, and GSAP timelines. Animation timing and the cursor element itself are visual-only and verified manually, consistent with `CONTEXT.md`. This split also closes #109.

This is the first nested folder under `components/ui/`; `0006-repo-structure.md` describes `ui/` as a flat bucket. A multi-file cursor with one test seam earns its own folder — the flat rule stands for everything else, and `CONTEXT.md`'s `components/ui/` note is updated to record the exception.

Cursor reduced-motion handling is owned by #121, which fades the whole cursor while the transition panel covers the screen. That toggles cursor opacity; this decision owns the per-element variant state. They touch the same element but not the same properties.
