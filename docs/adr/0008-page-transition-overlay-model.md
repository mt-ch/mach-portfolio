# Page transitions: a cover/uncover overlay, no `template.tsx`

Navigating between pages was a hard cut — the old route's content was replaced by the new route's with no visual continuity. Issues #118–#124 add a short cover/uncover transition to every client-side route change. The model it landed on, and why.

**An opaque overlay panel, not an animated page.** `PageTransitionProvider` (mounted once in the `app/(site)` route group layout, wrapping the chat shell and children) owns a single `fixed inset-0` panel. A forward navigation plays: **cover** (the panel sweeps down over the content area), then the route swaps *underneath* the stationary opaque panel and the scroll container is reset to the top, then a brief **hold**, then **uncover** (the panel lifts away while the incoming content rises ~16px and fades in, overlapping the tail of the lift). The panel sits at `z-[5]` — above page content but below the persistent chrome (`z-10`) and the chat drawer (`z-20`/`z-30`), so the logo, theme toggle, and "Ask" launcher stay visible and interactive throughout and the transition reads as the content area changing scene rather than the whole window flickering. While covering or covered the panel also captures pointer events, so links beneath it cannot be clicked mid-transition.

**There is deliberately no `template.tsx`.** Next's `template.tsx` remounts its subtree on every navigation, which is the usual hook for enter/exit animations. We do not use it. The outgoing page is never cloned, frozen, or animated — the opaque panel simply hides it, the route swaps behind the panel, and the new page is what gets revealed. This keeps the mechanism to one component and one plain DOM element: no per-route remount cost, no coordinating an exit animation against React unmount timing, no duplicated DOM during the swap. The provider itself never remounts per route (it lives above the route in the `(site)` layout), matching the custom-cursor idiom (see `0007-custom-cursor-interaction-model.md`).

**The panel colour is read from `--background` at animation time.** The panel's background is set from the `--background` CSS custom property just before each animation, so it tracks light/dark with no flash and no hardcoded colour. On first load the panel also renders opaque in the server HTML with `backgroundColor: var(--background)`, so the page is covered before any JavaScript runs (view-source / JS-disabled) and the first client render matches the server exactly.

**First load starts covered.** The reducer is seeded in the `covered` / `firstload` state so the server-rendered opaque panel is accounted for before hydration. After hydration the provider lifts it exactly once, gated on `document.fonts.ready` so text does not reflow under the reader, raced against a font cap so a slow or blocked font never strands the page. Browser back/forward cannot be intercepted before the URL changes, so `POPSTATE` also enters at `covered` and runs uncover-only — no cover phase, and no scroll reset (the browser's own scroll restoration stands).

**Timing tokens live in `lib/transition/constants.ts`.** Every duration and easing value — cover 400ms, hold 100ms, uncover 600ms, content rise 16px, first-load font cap 600ms, safety cap 1200ms, reduced-motion fade 150ms, and the `power2.in` / `power2.out` eases — is defined once there and imported by `PageTransitionProvider`. No transition component hardcodes a value. This mirrors `lib/theme` and means the feel can be retuned from one file. `CONTEXT.md`'s structure section is updated to record the `lib/transition/` constants module and the `components/features/transition/` bucket.

**Reduced motion is an opacity-only fade.** A `gsap.matchMedia()` split re-evaluates `(prefers-reduced-motion: reduce)` live, so a change to the OS setting takes effect on the next navigation with no reload. When it matches, every phase becomes a 150ms opacity crossfade of the panel: no vertical sweep, no content rise, no hold. The reduced-motion branch shares the same reducer and the same constants — only the GSAP branch differs.

**Cursor coordination is a plain DOM flag.** While the panel covers the page the provider sets `data-page-covered` on `<html>`; the custom cursor watches that attribute and fades out, so a lone cursor is never left floating on the blank panel. A DOM flag rather than a shared import keeps the generic cursor free of any page-transition knowledge — the same pattern `0007` uses for `data-chat-open`.

**The `transitionPhase` reducer is the one pure test seam.** All "what phase are we in" branching — forward nav vs. back/forward vs. first load vs. safety-cap, plus the `shouldResetScroll` and `shouldFadeCursor` intent flags the provider acts on — lives in `transitionPhase`, a framework-free `(state, event) => result` function with no React, GSAP, or DOM dependency. Its unit tests drive event sequences and assert the phase sequence and the intent flags for each scenario. `PageTransitionProvider` and `TransitionLink` additionally have behaviour-level tests (GSAP stubbed to fire completion callbacks synchronously) that assert observable outcomes — a click to a new path starts the transition, a same-path or external link does not, the route push and scroll reset happen while covered, the panel reveals within the safety cap. Consistent with `CONTEXT.md`, none of them assert markup, class names, or GSAP call shapes; the panel element and the animation timing itself are visual-only and verified manually, exactly as the custom cursor and chat-drawer timing are.

**`TransitionLink` is the single documented way to add a transitioning link.** It wraps `next/link`: a plain left-click to a different in-site path is intercepted and handed to the provider; everything else — external URLs, `target="_blank"`, modified clicks, hash/query-only changes, and the case where there is no provider above it — falls through to normal link behaviour untouched, so the site still works with JavaScript disabled. The four internal-navigation call sites (site logo, featured project row, project card, other-projects list) use it; external project links stay as plain `next/link`.
